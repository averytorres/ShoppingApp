Automatic Chrome launch
Under Connect a browser, link each account to the PC Chrome profile signed into that Walmart account. Only profiles with this grocery extension installed are offered. Profiles stay signed into their own Walmart accounts; labels do not validate Walmart identity.

Cart sync and headless runner (0.3.0)
Each connected account has its own live site cart. With the updated extension, idle checks refresh the normal Walmart cart about every 30 seconds. One cart update runs at a time per account; conflicting edits stop for review. Saved favorites and history are separate. Check Walmart cart now requests a read only. Purchase complete records a manually confirmed purchase, clears only the site cart and suppresses re-import of the old Walmart cart until an empty cart is observed or a deliberate new site edit starts another shop. It never submits checkout or removes Walmart items. Empty carts are not automatically classified as purchases.

Reorder suggestions
Suggestions use only manually completed purchases, not legacy cart-addition/debug history. Timing is estimated from up to one year of each account's completed shops, requiring at least three distinct purchase days and two intervals of at least two days. The median interval and recent median quantity are shown for items due within three days, excluding items already in that account's live cart. These are estimates, never automatic cart additions. Mark real shops Purchase complete to improve them.

Paste a list
The list planner supports newline/comma/semicolon-separated names, leading package counts (2 milk or 2x milk), trailing counts (milk x2), saved household product/quantity defaults, and explicit associations. Defaults and rules are shared household-wide; the destination cart remains account-specific. Familiar defaults preselect exact learned products. Unknown items require a choice or explicit exclusion. No fuzzy guess silently selects a product. Association expansion visits each term once, preventing cycles and duplicate extras. Include rules start checked; suggest rules start unchecked. The user reviews full product names, quantities, reasons and combined targets before submitting a single cart job. Existing quantities are preserved when already sufficient. Remember checkboxes save mappings after reviewed submission. Availability is confirmed by Walmart during the normal job; alternatives are not silently substituted. Only learned products with an offer ID can be selected; capture missing products on Walmart first. No example butter/papaya rule was seeded in the live database.

Purchase-history backfill
Shopping history now accepts normalized JSON/CSV files through an explicit preview and selected-order import. Download the format examples from the site; fictional example identifiers are blocked from import. Store/account/order identity is hashed for duplicate detection. Only completed/delivered/fulfilled/picked-up orders and eligible completed items import; canceled/returned/refunded orders/items, unconfirmed statuses, future/invalid dates and invalid quantities are excluded with preview reasons. Extra receipt fields such as addresses or payment details are discarded; raw files and original order identifiers are not stored. Optional unit prices are retained as provided. Commit is transactional and retry-idempotent. History imports never create cart jobs or send retailer requests. Walmart orders with valid product IDs feed reorder suggestions; missing IDs remain history-only. Imported items without offer IDs must be learned through Walmart before cart use. HEB purchases are stored with store attribution and excluded from Walmart recommendations/products. The chosen household account owns the imported store history; choose carefully in the preview.
This is the normalized import pipeline, not a verified Walmart/HEB website extractor. Real authenticated order-history layouts are still needed to implement and validate automatic collection. The current account has no known purchase history; the parser, API, duplicate checks, store separation, recommendations and mobile UI were validated with isolated fictional fixtures, never seeded into the live database.
